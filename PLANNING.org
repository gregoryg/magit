* Goal and boundary

Make the repository list a dependable daily dashboard:

- fetching never blocks Emacs, which is fatal under EXWM;
- a fetch that fails, especially for a missing SSH key, is visible in the list;
- the global list and per-directory lists are selected correctly; and
- marking and bulk commands work when the list uses =tabulated-list-groups=.

Changes useful to every Magit user are shaped as upstream topics.  Personal
taste, such as the filter-group definitions, flag glyphs, and key choices,
stays in Gregory's config.

* Problem analysis (2026-11-21)

Findings from reading =lisp/magit-repos.el= at upstream =7a05d472= and Emacs
32 =tabulated-list.el= and =outline.el=.

** Per-directory list opens on every call

=magit-repolist-setup= decides whether to show a per-directory list with
=buffer-local-boundp=, which is true for every bound variable, including a
globally customized =magit-repository-directories=.  Verified in batch Emacs:
=buffer-local-boundp= returns =t= where =local-variable-p= returns =nil=.  The
regression came with =3680327c= and =40310490= (per-directory lists, 2026-10).
Fix: test =local-variable-p=.  Workaround: advice
=gjg/magit-repolist-force-global=, which also discards the prefix argument.

A smaller flaw in the same feature: the per-directory buffer is named after
the invoking buffer's directory rather than the list's directory, so the same
list can open in several buffers.  Kept as a separate topic.

** Group header lines are collected as repositories

=magit-repolist--marked-repos= treats any line not starting with a space as
marked, and group headings start with =*=, the mark character.  With =all=,
=magit-repolist--mapc= collects every line.  Both yield =nil= ids, and
=expand-file-name= then signals.  Fix: skip lines without a
=tabulated-list-get-id=.  This is harmless on Emacs 28, where groups do not
exist.  Both functions date from 2022 (=f0296148=); groups arrived in Emacs
30.1 three years later, and Magit does not group repositories itself.
Workaround: =gjg/magit-repolist--target-repos=.

** Group heading highlight is lost

Tabulated-list buffers have no font-lock keywords, so
=outline-minor-mode-highlight= falls back to one-shot overlays.  The mode
hook runs before entries are printed, so nothing is highlighted until a revert
(=g=), which runs =outline-revert-buffer-rehighlight=.  The first mark calls
=magit-repolist--ensure-padding=, which reprints the buffer and drops the
overlays.  Marked rows also begin with =*=, so the default =outline-regexp=
makes them level-1 headings, which breaks folding and heading motion.  This
only matters with grouping, so it is fixed in config unless grouping goes
upstream.

** Marks do not survive a redraw

Marks exist only as text in each row's padding, so every full redraw erases
them: =g=, sorting by a column, and the =magit-refresh= that follows each
repository's fetch.  Reproduced in batch on 2026-11-21; the redraw code is
unchanged upstream code.  The last case means a failed bulk fetch cannot
simply be re-run on the same marks.  Emacs's own list modes behave the same
way.  The UPDATE mode of =tabulated-list-print= keeps tags only on unchanged
rows, and only when the list is sorted, so it does not help: after a fetch,
the marked rows are the ones that changed.

Fix: keep marks in a buffer-local table from repository id to mark, which
=m=, =u=, and =U= maintain, and set =tabulated-list-printer= to a function
that prints each entry and then reapplies its mark.  Every redraw goes
through the printer, including sorting and the per-row updates planned for
fetch.  Both pieces exist in Emacs 28.

** No command to unmark all

Upstream has =m= and =u= only.  =tabulated-list-clear-all-tags= exists since
Emacs 27.1, but signals an error while the padding is 0, before anything
was marked.  With marks kept in a table, =U= must clear the table too, or
the marks return at the next redraw, so =U= shares the topic
=repolist/marks=.

** Fetch blocks Emacs and hides failures

=magit-repolist-fetch= runs =magit-run-git= per repository, which calls
=process-file= synchronously.  Under EXWM, Emacs is the window manager, so
the whole desktop freezes.  A synchronous child has no pty, so when the SSH
key is not in the agent, ssh's passphrase prompt goes nowhere and the fetch
hangs until =C-g=.  Errors are invisible: =magit-process-finish= prints
=Git error: …=, which =magit-repolist--mapc= immediately overwrites with
=…done= and the next progress message.  Asynchronous Magit processes use a
pty and recognize passphrase prompts, which is why fetching from a status
buffer works.

Refreshing the list is synchronous as well: every column runs at least one git
command per repository, and TRAMP repositories pay a round trip for each.
Bulk fetch multiplies this: =magit-run-git= ends with =magit-refresh=, which
reverts a tabulated list, so fetching N repositories refreshes the whole list
N times (observed in batch, 2026-11-21).

* Fetch design (open)

Requirements:

- non-blocking, one repository at a time or a small fixed concurrency;
- fail fast when credentials are missing, with no prompting during a bulk
  fetch (decided 2026-11-21: Gregory prefers fail-fast over prompting);
- per-repository outcome visible in the list, plus a summary message;
- each row refreshed as its fetch completes;
- a way to cancel, and to re-run on failed or marked repositories, which
  needs marks to survive the fetch; and
- correct behavior for TRAMP repositories.

Candidate approaches:

- *A: environment* — bind =GIT_SSH_COMMAND= to =ssh -o BatchMode=yes= and
  =GIT_TERMINAL_PROMPT=0=.  Simple, but overrides a user's
  =core.sshCommand=, and propagation through TRAMP needs checking.
- *B: detect and abort* — run with =magit-start-git= (pty).  When
  =magit-process-password-prompt-regexps= matches during a bulk fetch, kill
  the process and record "needs credentials".  Respects SSH configuration,
  reuses Magit's own prompt detection, and covers HTTPS prompts too.

Recommended: B.  Findings from =lisp/magit-process.el= and batch probes on
2026-11-22:

- =magit-process-filter= calls Magit's password, username, and yes-or-no
  handlers itself, before =magit-process-prompt-functions=, so that hook
  cannot intercept a prompt.  A bulk fetch must install its own filter on
  the process returned by =magit-start-git= (the docstring of
  =magit-start-process= allows replacing filter and sentinel) and pass all
  other output on to =magit-process-filter=.
- With a pty, Magit's local default, a passphrase prompt from a real
  =git fetch= reached such a filter, which killed the process at once.
  Tested with OpenSSH's own prompt, using =ssh-keygen -y= as
  =core.sshCommand=.
- Magit's existing regexps recognize the four prompts a fetch is likely to
  meet: SSH passphrase, HTTPS username, HTTPS password, and ssh's host-key
  question.  The outcome can name which one stopped a repository.
- =magit-process-sentinel= refreshes the buffer that started the process,
  which reverts the whole list, so bulk fetch needs its own sentinel too.
- TRAMP is unverified, because perihelion cannot ssh to itself.  Magit uses
  pipes for remote processes; either the remote ssh's prompt reaches the
  filter, or ssh finds no terminal and fails at once.  Both fail fast; check
  from the EXWM host.
- Cause of the freeze, confirmed on the EXWM host 2026-11-22: Emacs has no
  controlling terminal, =DISPLAY= is =:0=, =SSH_ASKPASS= is empty, and
  =/usr/bin/ssh-askpass= is installed.  The synchronous =process-file= gives
  ssh no terminal, so ssh runs the default askpass program, whose X window
  EXWM cannot manage while Emacs waits for ssh.  With a pty, ssh prompts on
  the pty instead, which the bulk-fetch filter catches.

Proposed design:

- =f= keeps its selection (marked repositories, or all after confirmation)
  but fetches one repository at a time, asynchronously, starting the next
  one from the sentinel.
- Each fetch runs =remote update= through =magit-start-git=, as now, with a
  filter that kills the process on any prompt, and a sentinel that records
  the outcome, lets =magit-process-finish= log it in the process buffer,
  updates that repository's row, and starts the next fetch.
- Updating a row reformats its entry and reprints that line, keeping its
  mark, so this topic does not depend on =repolist/marks=.
- The echo area shows progress; at the end, a summary names each failed
  repository and why it failed.

Decided by Gregory, 2026-11-22: approach B, and

- after a run, exactly the repositories that failed are marked, so that
  =f= again retries only those; a cancelled run leaves the unfetched ones
  marked too;
- =f= during a running fetch offers to cancel it.  This may be
  controversial upstream, but suits daily use; and
- fetching is sequential, because one fetch at a time is easier to watch
  and test.  Revisit concurrency after experience with it.

* Grouping upstream (open)

Filter groups like ibuffer's would help anyone with many repositories.
=tabulated-list-groups= needs Emacs 30, while Magit supports 28.1, so an
upstream version would have to degrade gracefully.  Decide after the fixes
above; a good subject for a GitHub Discussion.
